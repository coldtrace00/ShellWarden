# ShellWarden — SSH-клієнт для Windows 10/11 і Linux

[English](README.md) · **Українська**

Відкритий SSH-клієнт на Qt 6 / QML: можливості PuTTY, інтерфейс у стилі Termius, акцент на безпеці.

## Можливості

**Підключення**
- **Хости**: картки з кольором і аватаром, групи, пошук, швидке підключення `user@host:port`.
- **Індикатор онлайн** на кожній картці (зелений / червоний, із часом відповіді; типово вимкнений, Налаштування → *Показувати, які хости онлайн*): поки відкритий список хостів, раз на 5 хвилин одне коротке з'єднання з кожним хостом через його ж проксі. Хости через Tor, Cloudflare чи jump-хост, а також прямі при увімкненому kill switch не перевіряються.
- **Вкладки**:
  - перетягування;
  - статус і колір хоста;
  - значки проксі, jump і тунелів;
  - контекстне меню: дублювати, в окреме вікно, розділити, закрити.
- **Розділений екран** (Ctrl+Shift+D): дві сесії поруч.
- **Окреме вікно**: будь-яку сесію можна винести в окреме вікно і повернути назад.
- **Права кнопка на хості**: *Підключитися один раз через* (маршрут лише для цієї вкладки) і *Завжди підключатися через* (зберігається в хості).
- **Jump host (ProxyJump)**: маршрут проксі → jump → хост.
- **Тунелі** L / R / D (SOCKS5): задаються в хості або відкриваються на льоту. Панель з анімованою схемою потоку і лічильниками трафіку.
- **SFTP-панель** (працює прямо під час SSH-сесії, через те саме з'єднання):
  - навігація; адресний рядок з доповненням назв через **Tab**;
  - права доступу, власник, точний розмір вибраного файлу;
  - одна кнопка **Передати ▾**: *На сервер* (вибрати файли на цьому ПК) або *На цей ПК* (зберегти файли, вибрані на сервері; кілька — Ctrl / Shift + клік); перетягування з Провідника теж вивантажує на сервер;
  - **докачка**: обірване передавання продовжується з місця зупинки, коли запустити його знову (завантаження → `.part` поруч із файлом, вивантаження → `<назва>.swpart` на сервері, наприкінці перейменовується, права зберігаються);
  - перейменування, видалення, нова тека;
  - черга передавання зі скасуванням;
  - **редагування файлу прямо тут** (до 5 МБ, Ctrl+S, права файлу зберігаються) з підсвічуванням синтаксису і показом рядка/стовпця.
- **Serial (COM)**: швидкість, біти, парність, керування потоком.
- **Історія команд для кожного хоста** (Ctrl+Shift+H або кнопка з годинником): пошук команд, які ви виконували на цьому сервері, вставити в рядок або виконати знову. Зберігається зашифровано у сховищі; команда, набрана з пробілом на початку, не запам'ятовується (як `ignorespace` у bash).
- **Сніпети**: збережені команди та **скрипти .sh** (імпорт з файлу), нові — зверху. Зберігаються зашифрованими у сховищі. Скрипт надсилається одним блоком і виконується інтерпретатором з рядка `#!`. Відправка в поточну сесію або в усі одразу.
- **Монітор сервера** під терміналом: CPU, RAM, диск, uptime, мережа (один постійний канал, без додаткових входів).

**Термінал**
- libvterm: xterm-256color, true color, Unicode, alt-screen (mc, htop, vim), миша, bracketed paste.
- 39 колірних тем: **Midnight** (за замовчуванням: глибокий темно-синій, спокійні кольори), ShellWarden, Deep Navy, Classic Dark, Graphite, Blue Team, Dracula, Catppuccin, Rosé Pine, Kanagawa, Tokyo Night, Nord, Ayu, Night Owl, Synthwave '84, GitHub, Solarized… І власні теми.
- **Підсвічування виводу**: помилки, попередження, OK, IP, URL, шляхи, дати — лише у звичайному тексті, повноекранні програми (vim, mc, htop) не змінюються.
- Сигнал терміналу (Backspace у порожньому рядку тощо): нічого / блимання / системний звук.
- Вибір моноширинного шрифту; за замовчуванням лишається поточний.
- Як у PuTTY: виділення копіює, права кнопка вставляє.

**Ключі (Keychain)**
- Генерація Ed25519 / ECDSA / RSA під паролем.
- Імпорт OpenSSH, PEM і **PuTTY .ppk v2/v3**.
- У редакторі хоста ключ вибирається зі списку, звідти ж можна створити новий або імпортувати.
- `.pub` зберігається **одним рядком OpenSSH** (`ssh-ed25519 AAAA… comment`). RFC 4716 — лише окремим експортом.
- Приватний ключ експортується в OpenSSH-форматі з правами лише для поточного користувача.
- **На сервери**: публічні ключі додаються в `~/.ssh/authorized_keys` на багатьох серверах одразу — один ключ для всіх або свій для кожного; після цього хост може входити ключем.
- **Заміна ключа на серверах** (Ключі → На сервери → *Замінити старий ключ*): три безпечні кроки на кожному сервері — вхід як зараз і додавання нового ключа; вхід **лише** новим ключем і видалення старого; ще один вхід лише новим ключем і перевірка, що старого справді немає. Де новий ключ не працює, старий лишається, тож заблокувати себе неможливо. На новий ключ перемикаються лише ті сервери, що пройшли всі три кроки.
- **SSH-агент**: Pageant, служба Windows «OpenSSH Authentication Agent», ssh-agent, KeePassXC, YubiKey. Вхід ключами агента і **agent forwarding** (`ssh -A`) — вмикаються в хості.

**Безпека**
- **Сховище**: Argon2id (256 МіБ, 3 проходи) → XChaCha20-Poly1305. Заголовок автентифікований, щоденні резервні копії (14 днів).
- **Генератор паролів**: від 19 символів (довжина — повзунком), з оцінкою стійкості. Шкала довжини з позначками 8 і 19. Ручний пароль — від 8 символів, з попередженням і кнопкою «Я приймаю ризик».
- **Автоблокування**: через задану кількість хвилин або годин, при блокуванні Windows / сні, або «ніколи не блокувати».
- **Майстер-пароль для підключення** (розділ «Розширений захист» хоста): питається навіть при розблокованому сховищі; 5 невдалих спроб → блокування на 30 с. Пароль хоста і його приватний ключ (з паролем ключа) лишаються **зашифрованими вдруге**, поки сховище відкрите: їх запечатано ключовою парою, секретна половина якої виводиться з майстер-пароля (Argon2id з вартістю самого сховища) лише на момент підключення і одразу стирається. Ключ, яким користується такий хост, захищений для всіх хостів, що ним користуються. Вимкнення опції питає майстер-пароль. Після підключення сесія тримає потрібне в пам'яті, доки вкладку не закрито. Для справжньої 2FA налаштуйте її на самому сервері (PAM + Google Authenticator) — ShellWarden покаже запит коду сервера.
- **Known hosts**: перевірка відбитка, червоне попередження при зміні ключа; за бажанням перевірка SSHFP (DNS). Імена хостів у файлі **хешовані**, як `HashKnownHosts` в OpenSSH, тож файл не показує, куди ви підключаєтесь (сторінка «Відомі хости» показує імена ваших хостів, поки сховище відкрите).
- **Вставка**: з тексту, що вставляється, завжди вирізаються керуючі символи (ESC…), тож скопійований текст не може завчасно завершити bracketed paste і виконати команди; текст із переносами рядків (або дуже довгий) спершу показується і вставляється лише після підтвердження, як у Windows Terminal.
- **Завантаження по SFTP**: імена файлів із сервера очищуються (без `..\`, `/`, `\`, `:`, керуючих і bidi-символів, без `CON`/`NUL`…), тож ворожий сервер не може записати щось поза вибраною текою.
- **Текст від серверів показується як звичайний текст** (імена файлів, повідомлення, банери): ніколи як форматований, тож ніщо, надіслане сервером, не змусить програму завантажити картинку з мережі чи з мережевої теки Windows.
- **Нотатки до хоста**: зашифровані у сховищі, як паролі.
- **Маршрути**: SOCKS5 / HTTP CONNECT / **Shadowsocks** / Tor / **Cloudflare Tunnel** (ShellWarden сам запускає `cloudflared access tcp`; порт 22 на сервері можна закрити). DNS резолвить проксі. Перевірка показує затримку, вихідний IP і країну.
  - **Shadowsocks** (вбудований, без окремої програми). Усе до сервера Shadowsocks зашифровано й схоже на випадкові байти, тож мережа між вами не бачить ні цільового сервера, ні того, що це SSH — корисно там, де SSH або проксі блокують. Вставте посилання `ss://` (Outline тощо) або заповніть поля. Посилання з плагінами (`plugin=`) не підтримуються.
    - **Shadowsocks 2022** (рекомендовано): `2022-blake3-aes-256-gcm`, `2022-blake3-aes-128-gcm`, `2022-blake3-chacha20-poly1305`; пароль — base64-ключ сервера; identity headers (`iPSK:uPSK`, сервери з кількома користувачами) для aes-шифрів. Захист від повторених з'єднань; годинник сервера має відрізнятися не більше ніж на ±30 с.
    - **Старіші AEAD (2017)**: `chacha20-ietf-poly1305`, `aes-256-gcm`, `aes-128-gcm`. Чесно про обмеження самого протоколу (не цього коду): ключ виводиться з пароля через MD5 без солі, захисту від повторених з'єднань немає, а активне зондування сервера може його виявити. Використовуйте лише там, де на сервері немає новішого.
  - Будь-який проксі можна **вимкнути**, не видаляючи: його хости тоді підключаються напряму (з увімкненим kill switch — через проксі kill switch, ніколи напряму).
  - Біля «Сервер бачить вас як» термінал показує, як іде сесія: *через проксі*, *через jump-хост* або *напряму*.
- **IP у логах сервера**: читається `$SSH_CONNECTION` і показується адреса, яка потрапить в `auth.log`.
- **Kill switch**:
  - прямі з'єднання заборонені;
  - проксі перевіряється кожні **3 с** (інтервал налаштовується), вихідний IP — щохвилини;
  - якщо проксі впав, сесії закриваються протягом цих 3 с; якщо він почав виходити з реального IP — при наступній перевірці вихідного IP, тобто **до хвилини пізніше**;
  - на пряме з'єднання програма не перемикається ніколи.
- **Блокування брандмауером** (Windows): правило Windows Defender Firewall дозволяє ShellWarden.exe з'єднання лише з проксі і localhost, тож помилка в самій програмі не пустить SSH-трафік повз проксі. Обмеження: правило діє лише для ShellWarden.exe — `tor.exe` і `cloudflared.exe` окремі програми, а коли проксі вказано **ім'ям**, це ім'я визначає служба DNS Windows, а не ShellWarden. Для найсуворішого варіанту вказуйте проксі IP-адресою.
- **Журнал подій**: підключення, маршрут, IP, який бачив сервер, зміни сховища, ключів і хостів, спрацювання kill switch. Без паролів і ключів. Фільтри, пошук, експорт CSV. **Зашифрований на диску**: кожен запис — запечатаний «конверт» для публічного ключа журналу, тож запис іде навіть при заблокованому сховищі (наприклад, невдала спроба розблокування), а прочитати його можна лише з відкритим сховищем; на диску немає нічого відкритим текстом про те, куди ви підключались. Типово зберігається 30 днів (7 / 30 / 90 / 365, Налаштування) або вимикається. Відкритий журнал старої версії шифрується й видаляється при першому розблокуванні.
- **Тека даних закрита**: на Linux тека `0700`, файли `0600`; на Windows у неї власний список доступу (ви, SYSTEM, Адміністратори) — його ставить інсталятор, а програма перевіряє при кожному запуску.

**Інше**
- **Оновлення**: через GitHub Releases з обов'язковою перевіркою SHA-256 (файл `SHA256SUMS`). Ставляться лише оновлення, підписані ключем проєкту minisign (`SHA256SUMS.minisig`, ключ — у `minisign.pub`). Версія в підписаному коментарі, у тегу релізу й у назві файлу мають збігатися і бути **новішими** за встановлену, тож старий підписаний реліз не можна підсунути як «оновлення» (без відкату).
- **Бібліотеки**: libssh ≥ 0.10.6 (Terrapin, CVE-2023-48795), libsodium ≥ 1.0.18 і OpenSSL ≥ 3.0 обов'язкові під час збирання і перевіряються знову під час запуску (підмінену старішу DLL програма не прийме).
- **Мови**: English, Українська, Русский, Français, Español. Перемикаються без перезапуску.
- **Portable-режим**: усі дані поруч з .exe.

## Модель загроз

Від чого ShellWarden захищає, а від чого ні.

**Захищає**
- **Вкрадений чи скопійований диск / резервна копія**: сховище, його копії й журнал зашифровані (Argon2id + XChaCha20-Poly1305; запечатані «конверти» для журналу); `known_hosts` не містить імен хостів. Без майстер-пароля вони нічого не кажуть про ваші сервери.
- **Інший обліковий запис на тому самому комп'ютері**: тека даних для нього закрита (Linux `0700`/`0600`, список доступу Windows).
- **Мережа між вами й сервером** (провайдер, Wi-Fi, цензор): сам SSH, плюс проксі, Tor чи Shadowsocks, щоб вона не бачила, куди ви підключаєтесь; kill switch ніколи не підключається напряму.
- **Ворожий або зламаний сервер**: він не запише нічого поза текою, у яку ви завантажуєте, не змусить програму щось завантажити з мережі, надіславши текст, а змінений ключ хоста показується червоним.
- **Вставлений текст** із веб-сторінок: керуючі символи вирізаються, багаторядковий текст спершу показується.
- **Підроблене оновлення**: ставляться лише релізи, підписані ключем проєкту, з відповідною і новішою версією.

**Не захищає**
- **Шкідлива програма на вашому ж комп'ютері чи хтось з правами адміністратора на ньому**: вони можуть прочитати пам'ять запущеної програми (поки сховище відкрите, його вміст там розшифрований) або записати натискання клавіш. Від цього не захистить жодна локальна програма.
- **Сервер, на який ви входите**, бачить, що ви там набираєте; з переадресацією агента root на тому сервері може користуватися вашим агентом, поки ви підключені.
- **Той, хто тримає ваш проксі / Shadowsocks / вихідний вузол Tor**, бачить, куди ви підключаєтесь (але не те, що всередині SSH).
- **Слабкий майстер-пароль**: Argon2id робить підбір повільним, але не неможливим.
- **Відкриті сесії після блокування сховища**: вони працюють далі й тримають у пам'яті секрети, з якими увійшли, доки вкладку не закрито.

## Тести

`cmake -DSHELLWARDEN_BUILD_TESTS=ON`, потім:
- `tests/unit_tests` — без мережі: сховище (неправильний пароль, пошкоджений файл, підроблені параметри KDF), захищені секрети, зашифрований журнал, імена файлів із серверів, вставка, фільтри історії команд, хешований known_hosts, minisign і перевірки оновлень (зокрема відкат), виведення ключів Shadowsocks, BLAKE3 і посилання ss://;
- `tests/integration_tests` — проти справжніх OpenSSH, ssh-keygen, puttygen, ssh-agent, SOCKS5 / HTTP-проксі, shadowsocks-libev і shadowsocks-rust (їх запускає `sudo tests/integration/setup.sh`): ключі, SSH, агент, проксі, зміна ключа хоста, імпорт .ppk, SFTP, тунелі, jump-хост, усі шість шифрів Shadowsocks;
- `tests/fuzz/` — цілі libFuzzer для всього, що читає дані ззовні (ключі `.ppk`/OpenSSH, `ss://`, `~/.ssh/config`, файл сховища, підписи, known_hosts, рядки журналу, потік Shadowsocks).

GitHub Actions (`.github/workflows/ci.yml`) запускає все це при кожному push — збирання під Linux, ASan + UBSan, фазинг і збирання під Windows (MSYS2) з unit-тестами. Релізи, як і раніше, збираються й підписуються на комп'ютері автора.

Проблеми безпеки: див. [SECURITY.md](SECURITY.md). Зміни: [CHANGELOG.md](CHANGELOG.md).

## Мережеві з'єднання та зовнішні сервіси

У ShellWarden **немає телеметрії, аналітики чи звітів про збої**. Окрім ваших власних серверів, програма звертається лише до сервісів нижче, і до кожного — з однієї причини.

| Сервіс | Для чого | Коли | Що він дізнається |
|---|---|---|---|
| **ipinfo.io** (`https://ipinfo.io/json`) | Дізнатися, з якого IP і країни виходить маршрут. | Перед кожним SSH-підключенням (тим самим маршрутом, що й підключення: через проксі або напряму); коли ви натискаєте *Перевірити* біля проксі чи «Ваш реальний IP»; з увімкненим kill switch — щохвилини для кожного проксі, що використовується, і один раз при вмиканні kill switch. | IP, з якого прийшов запит (вихід проксі або ваш), і User-Agent `ShellWarden-SSH-Client`. Не дізнається, до якого сервера ви підключаєтесь. |
| **api.ipify.org** (`https://api.ipify.org?format=json`) | Те саме, запасний варіант. | Лише коли ipinfo.io не відповів. | Те саме. |
| **dns.google** (`https://dns.google/resolve`, DNS over HTTPS) | Знайти записи SSHFP для ключа сервера. | Лише якщо в Налаштуваннях увімкнено *Перевіряти нові ключі серверів у DNS (SSHFP)*, і лише коли ключ хоста новий або змінився. Іде через проксі хоста. | Ім'я сервера. |
| **api.github.com** і завантаження релізів GitHub | Перевірити й завантажити оновлення ShellWarden (`coldtrace00/ShellWarden`). | Через 4 с після запуску, якщо увімкнено *Перевіряти оновлення під час запуску* (типово так), і коли ви натискаєте *Перевірити зараз*. Завантажене перевіряється SHA-256 і підписом minisign до встановлення. | Ваш IP і те, що ви користуєтесь ShellWarden. Вимкніть автоматичну перевірку в Налаштуваннях, якщо не хочете цього. |

Через проксі **Shadowsocks** перевірка IP іде звичайним HTTP (порт 80): від вашого комп'ютера до сервера Shadowsocks усе зашифровано самим Shadowsocks; незашифрована лише коротка ділянка від того сервера до сервісу IP, і там немає нічого, крім запиту «який у мене IP».

**Інші з'єднання — лише з тим, що ви налаштували самі:**
- ваші сервери (SSH, Telnet), додані проксі, jump-хости;
- перевірка проксі (з увімкненим kill switch — кожні 3 с): лише TCP-з'єднання з самим проксі, без запитів в інтернет;
- індикатор онлайн на картках хостів (типово вимкнений): одне коротке з'єднання з кожним вашим хостом раз на 5 хвилин, без входу;
- **Tor**: програма `tor`, яку запускає ShellWarden, або ваш Tor Browser на 127.0.0.1 — до мережі Tor підключається сам Tor;
- **Cloudflare Tunnel**: програма `cloudflared`, яку запускає ShellWarden, підключається до Cloudflare (і може відкрити браузер для входу в Cloudflare Access).

Посилання в програмі (сторінка завантаження Tor, документація Cloudflare, цей репозиторій) відкриваються у браузері лише тоді, коли ви на них натискаєте.

Якщо і ipinfo.io, і api.ipify.org недоступні (їх блокує ваша мережа або проксі), перевірка показує обидві помилки, наприклад `no IP service answered (ipinfo.io: …; api.ipify.org: …)`. З вимкненим kill switch підключення все одно відбувається; з увімкненим — підключення, маршрут якого не вдалося перевірити, блокується.

### Як це влаштовано
- **UI-потік** (QML + `AppController`) ніколи не блокується мережею: кожна SSH-сесія має власний `SshWorker` в окремому потоці; звідти ж ідуть SFTP, тунелі, агент і монітор сервера (один постійний канал).
- **Маршрут** будується ланцюжком: `ProxyTunnel` (SOCKS5/HTTP/Shadowsocks/Tor/Cloudflare) → `JumpBridge` (jump-хост) → цільовий сервер. Kill switch і `FirewallLock` стежать, щоб з'єднання не пішло напряму.
- **Сховище** (`Vault`) — один зашифрований файл; секрети в пам'яті тримаються в `SecureBytes` і затираються після використання.
- **Оновлення** (`UpdateChecker`) — GitHub Releases API → вибір файлу під систему → перевірка `SHA256SUMS` і її підпису minisign → запуск інсталятора.

## Збірка і запуск

### Windows: що потрібно один раз
- **Qt 6.5 або новіший** (перевірено на 6.12) з [офіційного інсталятора](https://www.qt.io/download-qt-installer-oss), компоненти: *MinGW 64-bit*, а в *Developer and Designer Tools* — *MinGW*, *CMake*, *Ninja*.
- **MSYS2** у `C:\msys64` ([msys2.org](https://www.msys2.org)) — звідти беруться libssh, libsodium, libvterm. Ставити їх вручну не треба, це зробить `build.bat`.
- За бажанням **Inno Setup 6 або 7** ([jrsoftware.org](https://jrsoftware.org/isdl.php)) — для інсталятора `setup.exe`.

```
git clone https://github.com/coldtrace00/ShellWarden.git
cd ShellWarden
```

### Windows — один клік
Двічі клацніть **`build.bat`** у теці проєкту (або запустіть його з командного рядка).
Скрипт:
1. знаходить Qt (`C:\Qt\6.*\mingw_64`), MinGW, CMake, Ninja і MSYS2 (`C:\msys64`);
2. ставить у MSYS2 libssh, libsodium і libvterm (лише те, чого ще немає);
3. збирає програму в `build\` і запускає її.

Скрипт лише читає `C:\Qt` і нічого там не змінює.

**Інсталятор і portable-версія:**
```
build.bat package
```
У теці `dist\` з'являться:
- `ShellWarden-<версія>-portable.zip`;
- `ShellWarden-<версія>-setup.exe` — лише якщо встановлено [Inno Setup 6 або 7](https://jrsoftware.org/isdl.php). Під час встановлення питає теку, і всі дані потім лежать саме там, у `data\`;
- `release\` — обидва файли плюс `SHA256SUMS` і підпис `SHA256SUMS.minisig`, готові для завантаження в реліз на GitHub.

Повний лог збірки — `build\build.log`.

### Linux
```
./build.sh            # збірка і запуск (за потреби запропонує встановити залежності)
./build.sh package    # .deb і .tar.gz у build-linux/
./build.sh appimage   # один файл ShellWarden-<версія>-x86_64.AppImage для будь-якого дистрибутива
```
Скрипт підтримує Ubuntu/Debian, Fedora і Arch.

## Релізи та кнопка «Оновити» в програмі

Програма перевіряє **останній реліз** репозиторію `coldtrace00/ShellWarden` (вбудовано під час збірки, змінюється в *Налаштування → Оновлення*). Щоб оновлення спрацювало:

1. Збільшіть версію в `CMakeLists.txt`: `project(ShellWarden VERSION 0.3.1 …)` — вона має бути **більшою**, ніж у встановленої програми.
2. Зберіть: `build.bat package`. У `dist\release\` будуть рівно ті файли, що треба завантажити:
   - `ShellWarden-0.3.1-setup.exe` — для встановленої версії;
   - `ShellWarden-0.3.1-portable.zip` — для portable;
   - `SHA256SUMS` — контрольні суми (без нього програма оновлення не поставить);
   - `SHA256SUMS.minisig` — підпис (див. *Підпис релізів* нижче; `build.bat package` питає пароль ключа і робить його сам).
   
   Linux-збірку (`./build.sh appimage`) покладіть у ту саму теку і підпишіть ще раз: `tools/sign_release.sh <тека> 0.3.1` (він перераховує `SHA256SUMS` для всіх файлів).
3. На GitHub: **Releases → Draft a new release → Choose a tag** → `v0.3.1` → *Create new tag*, перетягніть усі файли з `dist\release\`, натисніть **Publish release**. Чернетки (*draft*) і *pre-release* програма не бачить.

   Опис релізу — це те, що люди побачать у вікні оновлення (і ще раз як *Що нового* після оновлення). Пишіть його для кожної мови окремо; програма покаже частину своєю мовою, а якщо такої немає — англійську:
   ```
   <!-- lang:en -->
   ### What's new
   - Faster connect

   <!-- lang:uk -->
   ### Що нового
   - Швидше підключення
   ```
   Коди: `en`, `uk`, `ru`, `fr`, `es`. Опис без цих позначок показується як є.
4. Під час запуску програма сама покаже вікно зі змінами і кнопками **Оновити зараз** / **Пізніше** / **Пропустити цю версію**. Або вручну: *Налаштування → Оновлення →* **Перевірити зараз** → **Завантажити** → **Встановити**. Інсталятор тихо ставить нову версію в ту саму теку; `data\` (сховище, ключі, налаштування) не чіпається. Portable-версія відкриває теку з перевіреним zip — розпакуйте його поверх старої.

Перевірка також іде автоматично через 4 с після запуску (вимикається там же).

### Підпис релізів
Кожен офіційний реліз підписано [minisign](https://jedisct1.github.io/minisign/). Публічний ключ лежить у [`minisign.pub`](minisign.pub) і вшитий у програму:

```
RWTHLqknA+zq3S01ZgYde9o4CH9nluIpmb4DfczkFneGo8f3I25KR5Mi
```

Програма ставить оновлення, лише якщо `SHA256SUMS.minisig` — правильний підпис `SHA256SUMS` саме цим ключем, а завантажений файл збігається з контрольною сумою. Підкинутий у реліз файл (наприклад, після крадіжки акаунта GitHub) буде відхилено.

Перевірити реліз самостійно:
```
minisign -Vm SHA256SUMS -P RWTHLqknA+zq3S01ZgYde9o4CH9nluIpmb4DfczkFneGo8f3I25KR5Mi
sha256sum -c SHA256SUMS        # Windows: certutil -hashfile <файл> SHA256
```

Для автора:
- `build.bat package` сам підписує `dist\release\` (minisign питає пароль ключа). Секретний ключ шукається в `%MINISIGN_KEY%`, `Desktop\minisign-keys\minisign.key` і `%USERPROFILE%\.minisign\minisign.key`.
- Підписати вручну: `powershell -ExecutionPolicy Bypass -File tools\sign_release.ps1 -Folder dist\release -Version 0.3.1` (Linux: `tools/sign_release.sh dist/release 0.3.1`). Для Authenticode додайте `-CertThumbprint`.
- Форки: покладіть свій ключ у `minisign.pub` (`minisign -G -p minisign.pub -s minisign.key`) або збирайте з `-DAPP_UPDATE_PUBKEY=none`, щоб вимкнути перевірку.

## Де зберігаються дані

| Режим | Тека |
|---|---|
| Встановлений через `setup.exe` | `<тека встановлення>\data\` |
| Portable (zip) | `data\` поруч з .exe — достатньо порожнього файлу `portable` біля програми |
| Запуск з `build\`, .deb, AppImage | `%APPDATA%\ShellWarden\` (Linux: `~/.local/share/ShellWarden/`) |

У теці лежать:
- `vault.swv` — сховище (хости, паролі, ключі, нотатки — усе зашифроване), поруч `vault.swv.bak`;
- `backups/` — щоденні копії;
- `known_hosts` — імена хостів хешовані;
- `settings.ini`;
- `logs/` — журнал подій, зашифрований (`journal.pub` — його публічний ключ; секретний — у сховищі);
- `backgrounds/` — картинки власних тем (якщо їх додано).

Інсталятор (`build.bat package` з Inno Setup 6/7) питає теку, і саме там усе й зберігається: `<тека>\data` (доступна на запис користувачеві, який встановлював, закрита для інших облікових записів комп'ютера і лишається при видаленні програми). Нова установка починається з чистого аркуша: нічого з `%APPDATA%` не підтягується (перенести дані можна через «Зберегти резервну копію» / «Відновити»). Оновлення ставляться тим самим інсталятором.

Для встановленої і portable-версії там же: `keys/` (сюди за замовчуванням зберігаються експортовані ключі), `updates/` (завантажені оновлення), `cache/`, `tor/` (якщо tor.exe запускає ShellWarden). У реєстр, `%APPDATA%` і теки користувача програма тоді нічого не пише; portable-архів (`build.bat package`) уже містить файл `portable`.

**У репозиторій нічого з цього не потрапляє**: `.gitignore` виключає `data/`, `*.swv`, `*.key`, `build*/` і `dist/`.

### Незалежна перевірка шифрування
```
pip install argon2-cffi cryptography
python tools\verify_vault.py "%APPDATA%\ShellWarden\vault.swv"
```
Скрипт розшифровує сховище еталонними бібліотеками, без коду ShellWarden і libsodium:
- Argon2id — argon2-cffi;
- XChaCha20-Poly1305 — `cryptography` (OpenSSL) і HChaCha20 з тестовим вектором.

Неправильний пароль або змінений хоч один байт дає FAILED.
